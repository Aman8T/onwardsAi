### 2.4 Honest Weekly news

**Problem**
- News over 60 days old was shown undated, as if it were this week's.
- Press releases appeared as news.
- `.env.example` showed `theverge.com,reuters.com`. Both are domains Anthropic's search cannot read, and naming one makes the API refuse the whole search, so copying that line would silently end all news.

**Change**
- **`backend/tayyari/weekly/ground.py`:**
  - `page_date()` reads the search result's own age: ISO, "October 30, 2026", "Oct 30, 2026", "30 October 2026" and "3 days ago";
  - an item's date is the search result's first, else the model's;
  - an item dated before the 60-day window or after tomorrow is dropped (`stale`);
  - a press-release or paid-content address (`press-releases`, `/pr-news/`, `/sponsored`, `/brand-connect`, `/partner-content`, `/advertorial`) is dropped (`press`).
- **`weekly/news.py`:** `readable_domains()` leaves out configured domains the search cannot read, and their subdomains. It logs `weekly_news_domains_unreadable` instead of sending them.
- **`backend/.env.example`:** names readable domains and explains the rule.
- **`core/settings.py`:** the docstring is updated.

**Tests**
- stale, future and edge-of-window dates;
- the search's date wins over the model's;
- 15 `page_date` forms;
- 5 paid or press paths;
- `readable_domains`;
- a configured blocked domain no longer stops the search;
- only blocked domains means no search at all.

**Fixture changes**

### 2.5 Indian amounts fill a resume's `[x]`

**Problem.** "Rs. 8 crores" was refused as "not a figure we can use". `_FIGURE` in `match/bullets.py` knew only `₹`, `$`, `€`, `£`, K/M/B, `lakh` and `crore`.

**Change.** `is_figure()` reads a value with the verifier's own number reader (`portfolio.ground.measures_of`), so what is accepted here is checked the same way later.
- Accepted: Rs./Rs/INR/₹, lakh(s)/lac(s)/crore(s)/cr, Indian digit grouping (`1,20,000`), `12 LPA`, `p.a.` and a trailing `+`.
- Still refused: "about 30", "30 or 40", "thirty", "35% of sales".

`_fill()` now merges the person's figure with the unit and currency already around the slot, so they are not doubled:
- `₹[x] crore` + "Rs. 3.2 crores" → "Rs. 3.2 crores";
- `₹[x] crore` + "3.2" → "₹3.2 crore";
- `by [x]%` + "6.4%" → "by 6.4%".

With the old check this doubling could happen with "₹3.2 crore"; accepting more spellings made it easy to reach, so it was fixed here.

**Tests**
- 21 accepted spellings and 14 refused ones;
- an end-to-end test where Meera's "₹[x] crore" line is filled with "Rs. 3.2 crores", verified, and the export opens.

**Race closed.** `put` now refreshes `created_at` when the same posting is stored again. The first reading's text and parse still stay. The match route stores the posting right before the match row that points at it, so the purge can never delete it in that gap.

**Tests**

- A maintenance test checks the `postings` step.
